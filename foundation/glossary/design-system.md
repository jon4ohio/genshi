# Design System

## Definition

An organizational system that coordinates shared intent, recorded decisions, governed artifacts, operating mechanics, and feedback loops for product experience.

## Why It Matters

Industry treats design systems as deliverables (libraries, files, sites). Genshi treats them as infrastructure the organization depends on. Without this definition, governance and operations are optional add-ons.

## Relationships

- **framework** — provides structure for building and running a design system
- **governance**, **lifecycle**, **capability** — constitutive parts of a design system, not accessories
- **artifact** — evidence the system exists; not the system itself
- **decision**, **meaning** — durable records and intent the system must maintain

## Common Misinterpretations

- Equating a design system with a component library, Figma file, or documentation site
- Treating a design system as a project with an end date rather than managed infrastructure
- Confusing Genshi (the framework) with an adopter's design system

## Genshi Interpretation

A design system is an **organizational system** (ADR-0002). Its health is measured by decision quality, governance, adoption, and semantic discipline—not catalog size.
