# Framework

## Definition

A structured body of principles, models, vocabulary, and decision discipline that defines how design systems are conceived, governed, evolved, and assessed.

## Why It Matters

Without a framework boundary, methodology collapses into tooling choices. Genshi separates what organizations must sustain from how they implement it.

## Relationships

- **design-system** — the subject a framework helps organizations build and run
- **principle**, **decision** — normative core of the framework
- **governance**, **lifecycle** — cross-cutting models the framework supplies
- **artifact** types (**token**, **component**, **pattern**) — conceptual categories the framework defines; implementations are adapters

## Common Misinterpretations

- Assuming a framework must ship code or UI to be valid
- Treating the framework as a single design system rather than the structure for many
- Replacing organizational ownership with framework documentation

## Genshi Interpretation

Genshi is a **design system framework**, not a component library. At v0.2.0, Phase 1 foundations (language, metamodel, governance, decisions) are complete; interfaces and tooling remain Phase 3+ direction.
